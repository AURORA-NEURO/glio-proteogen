## Safety and replay

- Seven controls and the M27-07 media boundary are checked before retirement decisions.
- Missing consent, unresolved identity, unsupported upstream, duplicate artifacts, incomplete
  migration, unverified archive, and active dependencies fail closed.
- Every result binds the exact request digest and is replay-verified; copied or tampered results
  are rejected.
- Strict result validation also requires an `EXECUTED` result to carry an `EXECUTED` retirement
  package, preventing self-rehashed contradictory lifecycle states.
- Executed package criteria, dependency migrations, preserved evidence, communications, archive,
  and configuration are retained exactly from the request before replay or result-digest checks.
- Executed package identity, version, lifecycle lock, and request-digest-derived package ID are
  closed before replay; self-rehashed package identity substitutions fail contract validation.
- Migration status is authoritative for active-dependency gating. Caller-controlled dependency
  identifiers are opaque and cannot manufacture an active finding by containing `active`; an
  `IN_PROGRESS` migration abstains even when its identifier has no such marker.
- Provenance binds the request-derived activity, actor/module metadata, request and source input
  digests, configuration and consent controls, and all seven upstream control decisions; rehashed
  provenance substitutions fail contract validation.
- The service emits only retirement/archival metadata and explicit uncertainty; no biology or
  authority inference is emitted.
