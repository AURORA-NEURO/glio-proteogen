## Replay-integrity hardening

Replay is now a deterministic regeneration check, not a digest-only
self-consistency check. The verifier canonicalizes the submitted result,
re-executes the evaluator from its bound request, and compares the complete
canonical result, including report, findings, provenance, evidence, support,
uncertainty, limitations, and terminal status. A caller that changes a nested
report or evidence value and recomputes `result_digest` is therefore rejected.
The locked evaluator includes both digest tamper and self-rehashed semantic
mutation scenarios; the latter protects against forged-but-self-consistent
reports and evidence records.

All evidence is local and reproducible; GitHub Actions status is reported
separately from the code gates.
