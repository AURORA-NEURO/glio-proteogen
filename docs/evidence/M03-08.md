## Locked risk controls

- All seven caller controls are checked before upstream outputs, artifact mappings, bytes, or
  archive members are traversed, sized, hashed, or constructed.
- The chain contains genuine strict M03-01 through M03-07 results. Every result remains internally
  digest-valid and immutable; packaging never replaces it with a caller-authored receipt shell.
- Each required upstream stage remains distinct. Seven stage-specific cases prove that one
  accepted stage never masks another stage's quarantine, abstention, or otherwise unreleasable
  disposition.
- Identity, predecessor-result digests, quality/artifact/harmonization bindings, analysis lineage,
  stage order, and support prerequisites close across the entire chain. An independently valid
  result from a different execution chain is not composable.
- The parent receipt binds exactly `complex_activity`, the packaged M03 identity resolution, and
  authorized intended-use evidence. Wrong parent, subject, or intended use fails before signature
  verification or archive construction.
- Eight caller members are exact: safe canonical path, media type, byte count, SHA-256 digest, and
  role. The archive contains no missing, extra, aliased, duplicate, absolute, drive-qualified, or
  traversal member.
- The generated manifest is canonical before verification. The signature statement binds that
  manifest digest; the generated verifier receipt is not an input to the signed digest, so no
  circular signature dependency exists.
- The injected verifier is a fixture seam. Tests assert exact inputs, one call, typed success or
  failure, and replay; they do not treat it as a signer, trust anchor, or cryptographic primitive.
- Archive headers and order are deterministic. Reordered set-like declarations produce complete
  result equality and byte-identical archive bytes.
- Result reconstruction rederives canonical-USTAR `byte_size` from the exact descriptor member
  inventory. Descriptor digest/content equality and authenticity are established only by the
  public verify API against supplied archive bytes; the result envelope alone does not claim
  either property.
- Strict reconstruction rejects coercion, unknown fields, invalid enumerations, stale digests,
  mismatched sizes, unsafe paths, malformed statements, unsupported algorithms, and excess shape.
- Output contains no caller bytes, raw spectra, peptide rows, upstream biological payloads,
  inferred protein/isoform/proteoform or complex activity, subtype/proteotype, kinase state,
  fusion interpretation, treatment advice, key material, signature secrets, or upstream mutation.

## Preregistered synthetic criteria

The canonical case releases one exact chain into ten archive members. Semantic reordering preserves
the complete typed result and archive bytes. The seven-stage matrix exercises one non-releasable
state per M03-01 through M03-07. Each cross-chain substitution is rejected even though the donor
result is independently valid. Integrity cases isolate byte, digest, size, missing/extra member,
duplicate/alias, and path failures. Signature cases prove exact manifest binding, unsupported,
unavailable, and rejected outcomes, one-call verification, non-circular receipt construction, and
replay. Strict cases reject coercion and stale derived values rather than repairing them. Privacy
recursively inspects typed output and the manifest. Withheld consent rejects before hostile chain
or artifact traversal. Recovery creates a new immutable superseding attempt without rewriting old
evidence. Exact maximum shape is 64 software and 64 reference records; first excess rejects before
archive construction.

These are deterministic fixture assertions, not estimates of signature security, signer
authenticity, provenance truth, scientific reproducibility, assay performance, biological
preservation, supply-chain integrity, transportability, or clinical utility. Signature override,
release exception, claim promotion, critical discrepancy, novel/OOD state, and unresolved
biological conflict require governed human review outside M03-08.

## Release receipt snapshot

The current pinned receipt records 168 focused M03-08 tests and 96.29% branch-enabled coverage
(1,328 statements, 342 branches), with the evaluator at 38/38 cases and 40/40 checks. The locked
10-iteration public-build benchmark records a mean of 1,285,940,740 ns and p95 of 1,390,956,500
ns against 2,000,000,000 ns and 3,000,000,000 ns budgets. These numbers are performance and
regression evidence only; they do not promote the module's claims ceiling.

`verify_m03_08_release.py` rejects duplicate/non-finite JSON keys or numbers, altered evaluator
inventory, stale coverage/package receipts, and (when supplied) any wheel or sdist whose exact
bytes, size, digest, or archive member count differs from the receipt. The package evidence is
bound to `SOURCE_DATE_EPOCH=315532800` and two byte-identical builds; isolated import is checked
separately. The verifier never authenticates a signer or upgrades synthetic evidence to scientific
or clinical validation.

```bash
uv run python -m evals.m03_08.run
uv run python -m evals.m03_08.benchmark --iterations 25
uv run python tools/verify_m03_08_release.py release-evidence/m03_08 --artifacts-dir <build-dir>
```
