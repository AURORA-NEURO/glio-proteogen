## Locked safety controls

- Seven control states are checked before queue traversal; consent, identity, quality,
  provenance, support, intended-use, and configuration failures fail closed.
- Only the exact M18-05 workflow-result media type is accepted. No upstream object is opened,
  traversed, mutated, relabelled, or replaced by a compact receipt.
- Each discrepancy has a reason code and each assignment is blinded. Missing assignment or
  non-evaluable history abstains without emitting a record; deferred critical review records an
  escalation, never a negative finding.
- Audit events are sequential, unique, evidence-bound, and locked. Replay recomputes both
  request and result payload digests and rejects tampering.
- All seven uncertainty dimensions are explicitly `not_estimable`; limitations state that
  adjudication is not a biological truth estimator. Parent output is never emitted.
- Strict JSON rejects duplicate keys, unknown fields, coercion, wrong media, and oversized
  payloads before unsafe traversal.

## Release review

The release workflow runs `evals.m18_06.run` and `evals.m18_06.benchmark` and stores their JSON
reports with the candidate evidence bundle. External review remains required for critical
discrepancy, OOD state, support override, claim promotion, release exception, and unresolved
conflict. This evidence is executable consistency evidence, not reviewer authorization.
