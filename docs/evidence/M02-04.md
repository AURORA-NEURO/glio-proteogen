# M02-04 evidence inventory

This is a proportionate G1 package for deterministic evaluation of synthetic identification QC
observations. It neither self-issues review nor claims scientific qualification.

| Evidence | Artifact | Verification |
| --- | --- | --- |
| Locked scenarios | `tests/fixtures/m02_04/scenarios.json` | exactly eight accepted, failed, non-evaluable, and authorization cases |
| Contract/module tests | M02-04 focused tests | strict shapes, thresholds, lifecycle aggregation, provenance, and safe failure |
| Executable eval | `evals/m02_04/run.py` | exact scenario replay, consent preflight, full-output order equality, and privacy scan |
| Broad benchmark | `benchmarks/m02_04_quality_metrics.py` | representative public batch latency tripwire |
| Traceability | `docs/traceability/GLIO-PROTEOGEN-M02-04.csv` | requirement-to-evidence mapping |

## Locked risk controls

- The policy governs exactly six public metric codes and binds approved configuration evidence.
- Observation states remain explicit; missing, censored, not-applicable, and unsupported values
  never become zero, absence, pass, or a negative biological result.
- Any failed metric or required non-evaluable metric quarantines the profile.
- Optional censored or not-applicable observations stay visible as not evaluable.
- Reordering thresholds and observations cannot alter any output field or serialized JSON.
- Outputs are metadata-only and cannot contain raw spectra, peptide rows, subtype interpretation,
  kinase activity, omics fusion, or treatment advice.
- Consent denial precedes observation traversal and computation.

Recovery means correcting the authoritative observation, assay profile, or policy and rerunning;
prior evidence is not mutated. Critical discrepancy, support override, and release exception
require governed review outside M02-04. This package is candidate engineering evidence only.

```bash
uv run python -m evals.m02_04.run
uv run pytest benchmarks/m02_04_quality_metrics.py --benchmark-only --no-cov
```
