# M01-07 evidence inventory

This is a proportionate G1 evidence package for deterministic unsupported-case and abstention
routing. It does not self-issue reviewer approval. Every fixture is synthetic and non-clinical.

| Evidence | Artifact | Verification |
| --- | --- | --- |
| Locked scenario corpus | `tests/fixtures/m01_07/scenarios.json` | all-dimension support, per-dimension abstention, missing/unknown, optional N/A, aggregation, and consent denial |
| Core correctness tests | M01-07 contract and engine tests | requirement matching, requiredness, reason/remediation mapping, ordering, provenance, and failure semantics |
| Executable eval | `evals/m01_07/run.py` | exact scenario replay, deterministic ordering, and closed-output checks |
| Microbenchmark | `benchmarks/m01_07_support_routing.py` | one broad representative public-engine latency tripwire |
| Traceability | `docs/traceability/M01-07.csv` | each requirement names executable evidence |
| Reviewer sign-off | protected release review | supplied by a governed reviewer, never by implementation or test code |

## Locked risk controls

- Every one of the eight closed support dimensions is evaluated under its own reviewed
  requirement.
- Unsupported, missing, and unknown required evidence produce typed abstentions and do not
  become negative biological findings.
- Not-applicable evidence is accepted only for an optional dimension that explicitly permits it.
- Multiple failures retain all reasons and remediations in canonical dimension order.
- Reordering evidence or profile declarations cannot change the semantic result.
- The output cannot contain raw spectra/sequences, upstream genomic or PTM payloads, inferred
  proteotype, kinase activity, treatment advice, or generic fused interpretation.
- Consent denial and unresolved identity/lineage fail before routing.

## Synthetic regression criteria

The locked corpus requires exact supported/abstained outcomes, dimension identifiers, reason
states, and remediation paths. Each unsupported dimension has an isolated fixture, and combined
failures must equal the canonical union of their isolated reasons. These checks establish
implementation behavior only. They do not validate the completeness or appropriateness of a
real-world support domain, estimate cohort coverage, or demonstrate clinical utility.

## Recovery and review

Recovery means replaying the unchanged content-addressed request under the same support profile
and policy and comparing the deterministic result. A changed observation, requirement, allowed
value, requiredness, remediation, profile, or policy is a new request and result; prior evidence
is not rewritten. Unsupported cases, support overrides, and release exceptions require governed
human review.

```bash
uv run python -m evals.m01_07.run
uv run pytest benchmarks/m01_07_support_routing.py --benchmark-only --no-cov
```
