# M01-04 evidence inventory

This is a proportionate G1 evidence package for deterministic quality metric computation. It
does not self-issue reviewer approval. Every fixture is synthetic and non-clinical.

| Evidence | Artifact | Verification |
| --- | --- | --- |
| Locked scenario matrix | `tests/fixtures/m01_04/scenarios.json` | exact request/result expectations for seven representative cases |
| Core correctness tests | M01-04 contract and engine tests | formula, direction, threshold, missingness, support, and provenance invariants |
| Transport checks | `tests/integration/test_m01_04_interfaces.py` | strict request handling and equivalent typed API/CLI results |
| Executable eval | `evals/m01_04/run.py` | exact scenario replay, input-order determinism, and output-boundary checks |
| Microbenchmark | `benchmarks/m01_04_quality_metrics.py` | broad representative public-engine latency tripwire |
| Traceability | `docs/traceability/M01-04.csv` | each requirement names executable evidence |
| Reviewer sign-off | protected release review | supplied by a governed reviewer, never by implementation or test code |

## Locked risk controls

- The engine evaluates only metric definitions selected by the approved assay profile and policy.
- Missing, below-detection-limit, not-applicable, and measured values stay distinct; no state is
  silently coerced to zero, absence, or failure.
- Required incompleteness, failed controls, and sample-context conflicts cannot produce an
  accepted profile.
- Unknown assay types fail strict request validation instead of borrowing thresholds from a
  different assay.
- Metric results are deterministic, sorted, bounded, and individually provenance-linked.
- Reordering definitions or observations cannot alter the canonical profile.
- The output preserves uncertainty, limitations, and support and cannot contain raw assay rows,
  proteotype interpretation, kinase activity, treatment advice, or upstream mutations.
- Consent denial and unresolved identity/lineage fail at the request boundary before metric
  evaluation.

## Recovery and review

Recovery means replaying the unchanged, content-addressed request under the same reviewed assay
profile and computation policy and comparing the deterministic result. A changed threshold,
observation, profile, or policy creates a different request and result; prior evidence is not
rewritten. Critical discrepancies, unknown assay types, support overrides, and release exceptions
require governed human review.

```bash
uv run python -m evals.m01_04.run
uv run pytest benchmarks/m01_04_quality_metrics.py --benchmark-only --no-cov
uv run pytest
```
