# M22-06 module manifest

M22-06 is the provisional robustness, shift, and out-of-domain challenge service beneath
protein-RNA discordance. Its implementation is bounded to caller-declared challenge scenarios,
OOD bands, observations, safe-failure reports, and review routing. It does not calculate a
protein-RNA discordance estimate and does not promote unsupported or out-of-envelope challenges
to negative evidence.

## Dependency boundary

The request retains an M22-05 result as an opaque artifact with media type
`application/vnd.glio-proteogen.m22-05+json`. M22-06 does not import an M22-05 runtime service,
reconstruct an M22-05 result, or infer the upstream ABI. The source-artifact set must retain the
upstream artifact exactly, and duplicate or substituted source identities are rejected.

## Locked safety behavior

Seven caller-declared controls are required before request traversal: approved configuration,
identity/lineage, provenance, consent, quality, support, and intended use. Every configured
challenge kind must be present exactly once. Supported in-domain scenarios produce a typed surface;
review-required and unsupported scenarios produce an abstained result with a safe-failure report,
finding, support disposition, evidence, provenance, and seven not-estimable uncertainty
dimensions. No result emits a parent estimate, identity inference, treatment recommendation,
kinase output, generic all-omics fusion, or unsupported negative finding.

## Reproducibility and recovery

Requests, results, scenario identities, request digests, result identifiers, result digests,
provenance, and evidence are canonical and replayable. Tampered content, stale result identity,
missing upstream retention, invalid control state, and malformed JSON fail closed. CLI output never
overwrites an existing path. Any future owner-approved ABI must supersede this provisional package
without mutating its evidence.

The legacy replay keyword cannot disable semantic verification: `replay=False`
is rejected. Verification must regenerate the complete robustness surface from
the bound request so a caller cannot re-sign a changed finding and present it as
an engine-produced result.
