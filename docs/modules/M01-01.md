# M01-01: protocol and metadata specification

M01-01 is the evidence boundary between upstream control objects and later analytical
modules. It registers an immutable protocol schema, validates a metadata document without
coercion, and emits only a schema receipt or conformance profile. All examples and locked
fixtures are synthetic and non-clinical.

## Algorithm

Validation is a deterministic, fail-closed pipeline:

1. Pydantic contracts reject unknown properties, mutation, coercion, nulls in required
   fields, and non-finite numbers.
2. Schema, assay, and specimen versions are matched exactly against the supplied protocol.
3. Protocol fields, vocabularies, units, and compatibility rules are indexed once by their
   stable identifiers. Construction rejects duplicate or dangling references. Unit codes and
   dimensions come from an embedded UCUM 2.2 subset; unitful fields declare a reference unit,
   and bounds, observations, and predicates are converted with deterministic Decimal affine
   transforms before comparison.
4. Document entries are indexed by JSON pointer. Unknown paths, required-field gaps, and
   cardinality violations become typed issues.
5. Every observed scalar is checked against its declared kind before pattern, range, unit,
   or controlled-vocabulary constraints. Booleans never satisfy integer/number fields.
   Patterns admit concatenation, character classes, anchors, escapes, and exact bounded
   `{n}` repetition only; variable-length quantifiers are rejected before regex compilation.
6. Every unresolved value is checked against the field's explicit missingness allow-list.
   Missingness remains an unresolved state; it never becomes a negative observation.
7. Compatibility predicates run over typed entries. A failed rule retains the rule's
   declared action: reject, quarantine, or human review.
8. Every generic upstream control decision must be explicitly `accepted`, identity lineage
   must be `resolved`, and consent must be `granted` before request hashing or event writes.
   Identity lineage is bound to a canonical digest of only the protocol-declared identity-key
   entries; a mismatch becomes a critical quarantine finding rather than trusted lineage.
9. Consent supplied by the upstream authority can tighten the result but is never inferred
   or rewritten.
10. Issues are sorted by stable structural keys. Decision precedence is `quarantine`,
   `reject`, `human_review`, then `conformant`, independent of input field order. Unsupported
   assay or specimen versions and every unresolved value quarantine for explicit review.

With `F` schema fields, `E` document entries, `O` observed values, `V` vocabulary terms, and
`P` predicate operands, indexing and predicate evaluation are `O(F + E + O + V + P)`.
Deterministic value-order-invariant diagnostics add `O(sum(n_i log n_i))`, where `n_i` is the
value count of entry `i`; auxiliary space is linear in the indexed schema, document, and
vocabulary content. No regex backtracking or cross-product search is permitted.

## Safe-failure semantics

Contract-invalid input and non-authorizing upstream decisions are rejected before canonical
request hashing or event commitment. Conformance failures are represented as stable issue
codes. Quarantined and review-required documents remain available for audit but cannot
masquerade as conformant. Upstream references are copied only as immutable, content-addressed
identifiers; raw upstream objects are not edited. Every output provenance record contains
exactly one privacy-minimized decision record for each of the seven upstream control roles.
Only identity lineage carries a subject-binding digest, and persisted evaluation events omit
the raw document identifier and submitted metadata values.

Client schemas may declare at most 998 limitations. Two output slots are permanently reserved
for the module-owned `metadata_conformance_only` interpretation ceiling and the
`external_controls_unverified` warning, so every receipt/profile remains within its 1,000-item
public cap without displacing either safety statement.

Replaying the identical request identifier and canonical payload is idempotent. Reusing a
request identifier with a different payload, or a schema identifier/version with different
content, is a typed conflict. The append-only event chain contains digests and evidence
references rather than raw metadata values.

The implementation selects the dossier's event-sourced quality-service architecture for
auditability and its deterministic quarantine-first algorithm for G0 decisions. For the owned
55-field profile only, a versioned multi-view nearest-medoid guard compares non-identifying
metadata to a locked 12-profile synthetic reference design. It is not fitted, trained,
calibrated, or biologically interpretive: it can retain ordinary conformance or add a generic
quarantine/review finding, never promote a result or emit internal cluster labels, neighbours,
feature values, or per-view votes. Artifact failure and insufficient evidence fail closed.

## Evidence gate

Gate G0 requires all of the following:

- locked valid and adversarial JSON fixtures;
- eight self-identifying JSON Schema Draft 2020-12 exports with locked URNs and digests,
  standard `uniqueItems`/conditional invariants, and documented `x-glio-*` runtime extensions;
- contract, property, and safety-policy tests;
- deterministic issue ordering and field-order metamorphic checks;
- compatibility, identity-binding, typed-control authorization, quarantine, consent, replay,
  conflict, provenance-reconstruction, and event-chain checks;
- the executable eval suite in `evals/m01_01/run.py`;
- microbenchmarks in `benchmarks/m01_01_validation.py`;
- lint, strict typing, coverage, audit, eval, and benchmark CI jobs.

The latency budget is 5 ms mean for the four-field reference case and 50 ms mean for a
500-field synthetic case on a normal CI runner. Isolated SQLite orchestration has a 100 ms
mean budget for a fresh register-plus-evaluate lifecycle and 10 ms for exact two-operation
replay. Database initialization is excluded from the fresh lifecycle timing but every round
uses a newly initialized database; the replay benchmark seeds its own two-event ledger. These
are regression tripwires, not clinical service-level claims. Benchmark results must always
state environment and sample count.

## Agent-facing extension rule

An agent adding a field or rule starts with a fixture and traceability row, then changes the
contract and implementation, refreshes the explicit schema snapshot in review, and runs the
eval and benchmark gates. A snapshot change without a described contract change is a
failure, not a file to auto-update. New outputs require a new module boundary; they cannot be
smuggled into the conformance profile as extra keys.
