## Rollback and recovery

1. Quarantine or reject the affected request without mutating upstream evidence.
2. Retain the immutable request, result or rejection evidence, profile/schema versions, and all
   content digests for audit.
3. Withdraw the affected reviewed profile or deployment version through the external governed
   release process; restore the last approved version if operational rollback is required.
4. Correct the authoritative protocol, profile, reference declaration, authorization source, or
   implementation and issue a new request with exact supersession provenance.
5. Replay all 46 cases, strict schema/interface checks, the 25-call benchmark, and recursive
   privacy/ownership oracles before release.
6. Bind reviewer sign-off to the replacement artifact and retain the prior result. Never delete,
   rewrite, re-sign, silently promote, or relabel the failed evidence.
