# GLIO-PROTEOGEN-M18-05 — workflow presentation workspace

M18-05 is a provisional, schema-first workflow presentation service beneath Spatial
proteomics. It turns caller-declared biomarker-panel review material into a complete,
human-review workspace with task summary, evidence summary, uncertainty, discrepancy,
provenance, and next-action views. It does not emit or promote the parent biomarker-panel
result.

## Authority and boundary

- Owner: Clinical science; safety class S2; evidence gate G4; parent `biomarker panel`.
- Provisional operation: `present_biomarker_panel_review_workspace`.
- Provisional contract: `0.1.0-provisional`; output media
  `application/vnd.glio-proteogen.m18-05+json`.
- Upstream binding: the exact caller-declared M18-04 intended-use artifact with media
  `application/vnd.glio-proteogen.m18-04+json`.

The implementation is deliberately limited to presentation and review preparation. It does
not perform kinase interpretation, generic all-omics fusion, treatment recommendation,
upstream mutation or relabeling, identity or consent inference, disagreement erasure, or
conversion of unsupported material into a negative claim. Evidence and provenance are
caller-declared and are not authenticated by this service.

## Locked contract behavior

1. Seven controls—approved configuration, identity/lineage, provenance, consent, quality,
   support, and intended use—are checked before request traversal. A failed or malformed
   control context fails closed with a sanitized authorization error.
2. A request binds the M18-04 media type, unique source artifacts, the upstream artifact,
   every section artifact, six required section kinds, and a default order whose first view is
   `task_summary`. The workspace repeats those closures and requires unique section IDs.
3. The six required views are task summary, evidence summary, uncertainty, discrepancies,
   provenance, and next action. The configuration is locked and carries an automation-bias
   warning. Every workspace requires human review and is limited to 32 sections and 32 next
   actions.
4. Supported requests produce a `presented` workspace. Unsupported support decisions produce
   an `abstained` result with no workspace, a typed finding, safe support status, and an explicit
   abstention reason.
5. Results contain typed evidence, seven uncertainty dimensions, control provenance,
   limitations, findings, the `biomarker panel` parent target, and `emits_parent=false`.
   Finding IDs and finding codes are unique.
6. Canonical request and result digests bind replay. Service and plugin verification rebuild
   the result from the exact request; digest or replay tampering is rejected.
7. The API and CLI parse JSON once, preserve sanitized errors, enforce authorization, expose
   schema export, reject duplicate/invalid JSON, and refuse overwrite or non-regular output.

## Architecture decision

The dossier lists event-driven/semi-supervised, typed-service/mixture-of-experts, and
signed-review/latent-class alternatives. G4 installs only a deterministic typed service:
Pydantic contract validation, authorization-first preflight, caller-declared view assembly,
canonical replay, and quarantine-first abstention. No model weights, fitting, database,
event log, evidence graph, external content dereference, or mutable persistence is installed.

## Evidence and release gates

The frozen synthetic fixture covers supported presentation, unsupported abstention, six-view
closure, replay, tamper detection, and authorization denial. Adversarial tests cover strict
parse-once behavior, forged or mutated plugin tokens, wrong upstream media, duplicate and
unknown artifacts, unsafe ordering, finding closure, API/CLI parity, sanitized errors,
non-overwrite output, and replay verification.

The release gate requires the focused contract/interface suite, Ruff, strict MyPy, branch
coverage of at least 95% over the M18-05 contract, engine, service, plugin, and adapter, the
six-case evaluator, a ten-call benchmark, wheel/sdist build, isolated wheel import, package
hash verification, and a clean diff. Benchmark budgets are software regression budgets only:
mean ≤2,000,000,000 ns and p95 ≤3,000,000,000 ns.
