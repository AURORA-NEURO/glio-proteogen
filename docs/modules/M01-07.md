# M01-07: unsupported-case and abstention routing

M01-07 evaluates already-authorized evidence against a versioned support-domain profile. It
checks eight closed dimensions—assay, specimen, disease class, quality, completeness, platform,
reference, and intended use—and emits only a support decision, typed abstention reasons, and
remediation paths. Proteotype is contextual downstream scope, not an output inferred here; this
module does not emit biological findings, kinase activity, fused omics interpretation, treatment
recommendations, or clinical claims.

## Routing boundary

1. Validate consent, identity/lineage, approved configuration, provenance, quality, support, and
   intended-use controls before support evaluation.
2. Bind the request to one closed, versioned support profile and policy. Every dimension has a
   declared requirement, accepted evidence states/values, requiredness, and remediation path.
3. Evaluate every dimension independently. Supported required evidence passes; explicitly
   unsupported evidence produces a typed abstention reason rather than a negative scientific
   finding.
4. Preserve missing and unknown required evidence as distinct abstention reasons. Neither state
   is interpreted as absence, normality, or unsupported biology.
5. Permit `not_applicable` only for a dimension whose reviewed requirement explicitly declares
   it optional and allowed. Required or undeclared not-applicable evidence abstains.
6. Aggregate every failing dimension in canonical dimension order. Multiple failures are never
   collapsed to an arbitrary first error, and each retains its own remediation.
7. Emit a closed, canonically ordered support result with uncertainty, provenance, evidence, and
   limitations. Submitted evidence and upstream objects remain immutable.

The first implementation is a deterministic support router, not an anomaly detector or learned
support-domain model. It does not infer nearby supported values, authenticate external evidence,
or promote an abstained request through a more permissive dimension.

## Evidence gate

Gate G1 uses a small synthetic, non-clinical fixture corpus:

- one request supports all eight dimensions;
- eight single-dimension requests each route the exact unsupported reason and remediation;
- missing and unknown required evidence abstain without becoming negative findings;
- optional not-applicable evidence is supported only where declared;
- multiple failures aggregate in deterministic dimension order;
- consent denial fails at strict request validation;
- reversed observations and profile declarations replay identically; and
- a recursive boundary check excludes raw payload, proteotype, kinase, fusion, treatment, and
  upstream-mutation fields.

These are exact deterministic routing fixtures, not validation of a real support domain,
transport performance, cohort coverage, calibration, or clinical utility. One broad public-engine
microbenchmark is an algorithmic regression tripwire, not scientific evidence.
