# M01-05: artifact and contamination detection

M01-05 evaluates already-authorized, typed technical signals against a reviewed rule profile. It
emits artifact-class flags, bounded posteriors, and a deduplicated exclusion mask for seven
classes: technical artifact, contamination, barcode/index error, batch effect, low complexity,
mapping artifact, and context-specific false positive. Proteotype is only the contextual
downstream target; this module does not infer a proteotype, kinase state, biological absence,
treatment recommendation, or clinical claim.

## Detection boundary

1. Validate consent, identity/lineage, approved configuration, provenance, upstream quality and
   support, and intended use before evaluating any signal.
2. Bind the request to a closed detector profile, rule set, and policy. Each rule binds one
   signal and artifact class and is evaluated independently for every target carrying that
   target-local signal; a nearby rule is never substituted for an uncovered class.
3. Require every signal named by the applicable rules. Missing required material produces a
   typed non-evaluable flag and review outcome, not a clear finding.
4. Evaluate each applicable rule deterministically. If no rule triggers, emit the reviewed clear
   posterior. If one or more rules trigger, retain the maximum configured triggered posterior;
   independent rule values are not added or multiplied into invented confidence.
5. Apply the reviewed decision thresholds. Exclusion is possible only at or above the exclusion
   threshold when every triggered rule tied for the maximum posterior is exclusion-eligible.
   Values at or above the review threshold otherwise require review; lower evaluated values
   remain clear.
6. Construct the exclusion mask from unique target identifiers having at least one exclusion
   flag. Multiple artifact classes may flag one target, but never duplicate it in the mask.
7. Emit sorted flags, the exclusion mask, support, uncertainty, provenance, evidence, and
   limitations. Submitted signals and upstream objects remain immutable.

This first implementation is a compact deterministic framework, not a learned contamination
model. Profiles make signal requirements, comparisons, triggered/clear posteriors, eligibility,
and decision thresholds explicit data. A posterior is a reviewed rule output used for technical
triage; this evidence package does not claim cohort calibration or biological probability.

## Evidence gate

Gate G1 uses one small synthetic, non-clinical corpus:

- a compact labeled batch seeds every one of the seven artifact classes;
- clean eligible targets exercise the false-exclusion ceiling;
- one clean target verifies the explicit clear path;
- one missing-required-signal target verifies non-evaluable review;
- consent denial verifies authorization before detection;
- reordered targets, rules, and signals verify deterministic output; and
- a recursive boundary check excludes raw payload, proteotype, kinase, fusion, treatment, and
  upstream-mutation fields.

The locked seeded-class criterion is exclusion sensitivity at least `0.95`; the expected
synthetic replay is `7/7 = 1.0`. The locked clean-target false-exclusion ceiling is `0.05`; the
expected replay is zero false exclusions. These are deterministic regression criteria over a
small fixture, not estimates of real-world sensitivity, specificity, prevalence, or calibration.
One broad public-engine microbenchmark watches for algorithmic regression without treating
hardware timing as scientific evidence.
