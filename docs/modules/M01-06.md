# M01-06: harmonization and normalization

M01-06 applies reviewed, deterministic technical shifts to already-authorized quantitative
features. The initial profile estimates batch and platform offsets from declared controls,
emits a harmonized analysis object and transformation manifest, and verifies protected
biological direction and rank invariants before acceptance. Proteotype is only the contextual
downstream target; this module does not infer a proteotype, kinase state, generic multi-omics
fusion, treatment recommendation, or clinical claim.

## Harmonization boundary

1. Validate consent, identity/lineage, approved configuration, provenance, upstream quality and
   support, and intended use before reading quantitative observations.
2. Bind the request to one versioned harmonization profile and policy. All observations use one
   common declared additive scale/unit; feature, control, batch, platform, and
   protected-comparison declarations are explicit data.
3. Estimate each supported technical-stratum shift from control medians only. Biological samples
   never teach the correction applied to their own stratum.
4. Apply the declared bounded additive shift to observed values. Missing and censored values
   remain typed missing and censored states; neither is converted to zero or a pseudo-value.
5. Recompute the locked technical-spread and protected-biological checks. Accepted technical
   spread must be non-increasing and within tolerance while every protected direction and rank
   relation remains within tolerance. The supported fixture additionally requires actual spread
   reduction.
6. Quarantine insufficient control coverage, any shift that reaches the reviewed cap, residual
   technical spread above tolerance, and any protected invariant violation. A capped estimate
   and applied shift remain explicit in the quarantined manifest.
7. Emit canonically ordered harmonized values, a transformation manifest, typed support and
   uncertainty, provenance, evidence, and limitations. Upstream inputs remain immutable.

The first implementation is a compact control-median framework, not a learned representation or
a universal batch-removal method. It does not claim to resolve laboratory, build, depth, purity,
composition, or preanalytic effects unless a reviewed profile explicitly declares the effect,
controls, units, and acceptance checks. It preserves disagreement and abstains outside that
support envelope.

## Evidence gate

Gate G1 uses one small synthetic, non-clinical fixture corpus:

- declared batch and platform offsets in controls must have lower post-transform spread;
- protected biological direction and rank relations must remain unchanged;
- missing and censored observations must retain their typed states;
- insufficient controls, a capped correction, and an invariant violation must quarantine;
- consent denial must fail at strict request validation;
- reversed observations, strata, and invariant declarations must replay identically; and
- a recursive boundary check must exclude raw payload, proteotype, kinase, fusion, treatment,
  and upstream-mutation fields.

All numeric expectations are deterministic fixture-regression criteria. They are not cohort
validation, transport evidence, clinical performance, or proof that biological signal is
preserved beyond the declared synthetic relations. One broad public-engine microbenchmark is an
algorithmic regression tripwire, not scientific evidence.
