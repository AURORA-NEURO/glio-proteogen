# M01-03: raw-format ingestion and parser

M01-03 is the byte-to-contract boundary for raw proteomic and genomic inputs. It accepts a
bounded byte stream, verifies its optional SHA-256 checksum, detects compression and content,
and emits a validated raw-input descriptor plus typed parse diagnostics. It never retains the
raw payload in its result and never interprets the input as a proteotype, kinase state, fused
omics claim, identity assertion, negative finding, or treatment recommendation.

The first contract supports six deliberately narrow content profiles: mzML 1.1.0,
mzIdentML 1.2/1.3, mzTab-M 2.0.0 (`2.0.0-M` header), FASTA, VCF 4.1-4.5, and GFF3.
These are safe ingestion profiles, not claims of complete standards conformance. mzIdentML 1.3
and VCF 4.5 are the current canonical write targets while the listed earlier versions remain
readable. Downstream modules remain responsible for scientific validation and interpretation.

## Deterministic ingestion pipeline

1. Read bytes through a hard raw-size ceiling while computing the digest of the bytes exactly as
   supplied. Verify an optional SHA-256 value before decompression or content parsing.
2. Detect gzip from its magic bytes. A filename suffix is advisory and cannot override content.
   Decompress only within a separate decoded-size ceiling; corrupt streams are quarantined and
   resource-limit violations are rejected.
3. Run bounded content detectors. Exactly one supported profile must match. Unknown and
   ambiguous inputs are quarantined instead of guessed from the extension.
4. Parse with the selected strict profile. Versions, required structural markers, counts, and
   line or XML well-formedness are checked without network access or entity expansion.
5. Emit only a format identifier and version, media type, compression state, raw digest and
   sizes, one bounded structural record count, and ordered typed diagnostics. Sequence strings,
   spectra, variants, genotypes, feature attributes, and tabular rows are not copied into the
   result.
6. Treat malformed, unsupported, and ambiguous content as explicit quarantine outcomes. Reject
   checksum and capacity failures before deeper interpretation. Missing content never becomes a
   negative biological result.

The implementation is a single bounded pass over raw bytes plus, for gzip, a bounded pass over
decoded bytes. Its time cost is `O(raw bytes + decoded bytes)` and its memory is capped by the
active ingestion limits. Detection and blocking disposition depend on content and policy, not
process hash seed or filename; a misleading filename can add only a fixed advisory diagnostic.

The central `POST /v1/modules/M01-03/inspect` binary route applies these M01-03 limits directly:
256 MiB for supplied bytes and 512 MiB after decompression. It is intentionally exempt from the
central 4 MiB JSON transport ceiling; JSON routes retain that ceiling and verify routes retain
their separate result ceiling. This keeps the API transport boundary aligned with the parser
contract instead of rejecting valid raw sources before M01-03 can return a typed descriptor.

## Structural record count by profile

| Profile | Meaning of `record_count` |
| --- | --- |
| mzML 1.1.0 | spectra and chromatograms |
| mzIdentML 1.2/1.3 | spectrum-identification results and peptide-evidence records |
| mzTab-M 2.0.0 (`2.0.0-M`) | protein, peptide, PSM, and small-molecule data rows |
| FASTA | sequence records |
| VCF 4.1-4.5 | variant records |
| GFF3 | feature records before an optional FASTA section |

The detected version is retained separately. Counts describe container structure only and are
not evidence of biological presence,
absence, identity, quality, or clinical relevance.

## Evidence gate

Gate G0 uses one synthetic, non-clinical scenario matrix. It covers every supported profile,
checksum success and mismatch, gzip magic and corruption, malformed XML, unsupported versions,
unknown content, stream/byte equivalence, misleading filenames, and raw/decoded size limits.
The executable eval replays this matrix and verifies deterministic, privacy-minimized results.
Four microbenchmarks watch representative XML, text, tabular, and compressed paths with broad
regression budgets rather than hardware-sensitive optimization targets.
