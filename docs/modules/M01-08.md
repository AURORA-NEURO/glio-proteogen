# M01-08: provenance and release packaging

M01-08 packages already-authorized, closed artifacts into a deterministic release candidate. It
verifies path safety, byte length, SHA-256 identity, software/reference versions,
transformations, quality/support decisions, and reproducibility tolerances; emits a canonical,
closed package manifest; and binds—but never creates—an external signature receipt. Proteotype is only
downstream context. This module does not validate scientific findings, infer biological state,
own kinase activity, fuse omics, recommend treatment, or act as a signature authority.

## Packaging boundary

1. Validate consent, identity/lineage, approved configuration, provenance, quality, support, and
   intended use before reading or hashing artifact bytes.
2. Bind the request to a versioned packaging policy and exact artifact declarations. Each
   canonical relative path has one declared size, SHA-256 digest, media type, and role.
3. Reject absolute paths, traversal, duplicate canonical paths, byte-length mismatch, and digest
   mismatch. No unsafe or ambiguous member reaches the candidate package.
4. Canonicalize entries independently of input declaration or byte-map order, then construct the
   deterministic package and reproducibility manifest.
5. Record exact software versions, reference identities, transformation digests, upstream quality
   and support decisions, and a closed numerical-tolerance manifest. No version or tolerance is
   inferred from artifact content.
6. Require a caller-supplied external signature receipt that matches the package digest and
   declared authority. Missing or mismatched receipt blocks/quarantines release; M01-08 never
   generates keys, signatures, or reviewer approval.
7. Return the controlled canonical archive payload separately from the typed result. The typed
   result contains only the package descriptor, manifest, support/uncertainty, provenance,
   evidence, and limitations; it does not duplicate or retain source bytes.

The first implementation is deterministic packaging infrastructure, not a ledger, model,
signature service, or independent supply-chain trust root. Cryptographic hashes establish byte
identity and integrity under the declared algorithm; they do not prove scientific correctness,
authorship, or authority.

## Evidence gate

Gate G1 uses a small synthetic, non-clinical corpus:

- one three-artifact package reproduces bit-for-bit under reversed declarations and byte-map
  order;
- exact paths, sizes, digests, software/reference versions, transformations, quality/support
  decisions, and tolerance entries are locked;
- tampered bytes, wrong declared digest, traversal, and duplicate canonical path reject;
- missing or package-mismatched external signature receipts block/quarantine and are never
  replaced by a self-signature;
- consent denial occurs before any artifact byte read or hash;
- a recursive boundary check excludes source bytes, proteotype, kinase, fusion, treatment, keys,
  and self-signature fields.

These are deterministic package-reproducibility fixtures, not scientific-result validation,
signature authority, external trust establishment, or supply-chain qualification. One broad
public-engine microbenchmark is a representative latency regression tripwire, not scientific
evidence or an asymptotic-complexity claim.
